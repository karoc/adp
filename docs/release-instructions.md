# Release Instructions

Simplified Chinese: [release-instructions.zh-CN.md](release-instructions.zh-CN.md)

This guide is the operator procedure for publishing ADP stable release artifacts. It applies to the current `1.0.1` patch-prep release and to later patch releases with the version adjusted. ADP remains a terminal-first, local-first CLI; this process does not introduce hosted orchestration, dashboards, cloud sync, SaaS release tracking, automatic Git execution, or provider-managed Codex or Claude access.

## Release Scope

The current release target is `1.0.1`. The source default version is also `1.0.1`, but release artifacts must still carry explicit build identity:

- `VERSION`, normally `1.0.1`.
- `COMMIT`, normally the Git commit used for the release.
- `BUILD_DATE`, normally a UTC timestamp.

The canonical build script is `scripts/build-release.sh`. Do not use ad hoc `go build` commands for release artifacts unless you are debugging a failed build and then returning to the canonical script.

## Preflight

Start from the source form that will be released, usually a clean Git checkout. Record the local state before building:

```bash
git status --short --branch
git rev-parse HEAD
git check-ignore -v .envrc mvp.md || true
```

Run the standard aggregate gate:

```bash
scripts/check-all.sh
```

`scripts/check-all.sh` is the release decision gate. It warms the Go build cache, runs the provider-free smoke suite in parallel by default with timing output, then runs `scripts/check-coverage.sh`, `go vet ./...`, `scripts/check-file-lines.sh`, `scripts/check-docs-bilingual.sh`, and `git diff --check`.

If the gate fails, stop the candidate and use [release-troubleshooting.md](release-troubleshooting.md). Do not tag, announce, or publish artifacts from a failed source form.

## Build Artifacts

Build from the repository root with explicit identity values:

```bash
VERSION=1.0.1 \
COMMIT="$(git rev-parse HEAD)" \
BUILD_DATE="$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
./scripts/build-release.sh
```

The script writes the platform binaries and checksums under `dist/`:

```text
dist/SHA256SUMS
dist/adp-1.0.1-linux-amd64
dist/adp-1.0.1-linux-arm64
dist/adp-1.0.1-darwin-amd64
dist/adp-1.0.1-darwin-arm64
dist/adp-1.0.1-windows-amd64.exe
```

If the build source is an archive without `.git`, set `COMMIT` explicitly to the published commit hash or another stable archive identifier recorded in the release evidence:

```bash
VERSION=1.0.1 \
COMMIT=<published-commit-or-archive-id> \
BUILD_DATE="$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
./scripts/build-release.sh
```

## Verify Build Identity

Run at least one packaged binary and verify that it reports the release identity:

```bash
dist/adp-1.0.1-linux-amd64 version
```

Expected release output shape:

```text
adp version 1.0.1
commit: <commit>
built: <timestamp>
go: <go-version>
platform: <goos>/<goarch>
```

Artifacts that omit `commit:` or `built:` were not built with full release identity and must be rebuilt. Do not edit release evidence to match an accidental binary.

## Verify Checksums

Verify the checksum file generated by the build script before packaging or uploading artifacts:

```bash
cd dist
sha256sum -c SHA256SUMS
cd ..
```

If the operator platform does not provide `sha256sum`, use an equivalent SHA-256 verification command and record that command in [release-evidence.md](release-evidence.md).

## Package Contents

Each release package should contain one target-platform `adp` binary plus the required notices and release documents. Use the packaging contract in [release-packaging.md](release-packaging.md) as the source of truth. The current required contents include:

- `README.md` and `README.zh-CN.md`.
- `LICENSE`.
- `COMMERCIAL.md` and `COMMERCIAL.zh-CN.md`.
- `CONTRIBUTING.md` and `CONTRIBUTING.zh-CN.md`.
- `SECURITY.md` and `SECURITY.zh-CN.md`.
- `docs/license-policy.md` and `docs/license-policy.zh-CN.md`.
- `docs/release-packaging.md` and `docs/release-packaging.zh-CN.md`.
- `docs/release-evidence.md` and `docs/release-evidence.zh-CN.md`.
- A short release evidence note or release note with version, commit, target platform, gate result, and checksum.

Packages must exclude `.envrc`, `mvp.md`, `$ADP_HOME`, `$ADP_RUNTIME_DIR`, runtime overlays, logs, task state, credentials, machine-specific shell startup files, temporary release rehearsal directories, provider-native session state, and local ADP planning ledgers.

Record a sorted package manifest before publishing, for example:

```bash
tar -tf adp-1.0.1-linux-amd64.tar.gz | sort > adp-1.0.1-linux-amd64.manifest
```

Treat a manifest mismatch as a packaging failure. Rebuild from a clean staging directory instead of weakening the local-first package boundary.

## Install Rehearsal

Install at least one packaged binary into a temporary directory on `PATH` and run it from there:

```bash
ADP_INSTALL_BIN="$(mktemp -d)"
install -m 0755 dist/adp-1.0.1-linux-amd64 "${ADP_INSTALL_BIN}/adp"
export PATH="${ADP_INSTALL_BIN}:${PATH}"
adp version
```

Then run a provider-free first-run rehearsal with temporary `ADP_HOME`, temporary `ADP_RUNTIME_DIR`, a temporary project root, and fake local agent commands. The rehearsal should prove that the installed binary can initialize ADP state, register a workspace, run workspace diagnostics, launch `adp run codex --workspace <name> --task <task-id> -- <agent-args>` against a fake `codex`, inspect events and sessions, and leave the real project root free of ADP-generated files.

Optional real Codex or Claude checks are separate operator evidence. Do not make real provider credentials, quota, model access, network availability, or interactive session behavior part of the default release gate.

## Release Evidence

Record release evidence after the gate, build identity check, checksum verification, package manifest inspection, install rehearsal, and any applicable source archive rehearsal pass. Use [release-evidence.md](release-evidence.md) and keep required provider-free evidence separate from optional real-agent evidence.

At minimum, the evidence should include:

- Version `1.0.1`.
- Commit and source form.
- UTC build date.
- Go version.
- Target platform and artifact filename.
- `adp version` output from the packaged binary.
- SHA-256 checksum and verification command.
- `scripts/check-all.sh` result.
- Package manifest path or inline manifest excerpt.
- Install-from-artifact rehearsal result.
- Source archive or no-`.git` rehearsal result when applicable.
- Optional real-agent tiers recorded as passed, failed, deferred, or `not run`.

Do not include credentials, account identifiers, private prompts, provider-native session files, sensitive model output, or machine-local ADP ledgers in evidence or packages.

## Tag And Publish

Create a release tag only after the source form is clean, the gate has passed, artifacts have been built and verified, and release evidence is complete. The tag must point at the same commit used for `COMMIT` in the artifacts.

```bash
git tag -a v1.0.1 -m "ADP 1.0.1"
git push origin v1.0.1
```

Publish artifacts only after the tag points at the release commit. If using GitHub Releases, upload the checked binaries, `dist/SHA256SUMS`, package archives, package manifests, and the release evidence or release note. A `gh` CLI command can be used when the operator has sufficient permissions:

```bash
gh release create v1.0.1 \
  --title "ADP 1.0.1" \
  --notes-file <release-note-file> \
  dist/adp-1.0.1-linux-amd64 \
  dist/adp-1.0.1-linux-arm64 \
  dist/adp-1.0.1-darwin-amd64 \
  dist/adp-1.0.1-darwin-arm64 \
  dist/adp-1.0.1-windows-amd64.exe \
  dist/SHA256SUMS
```

If release creation fails because of token permissions, keep the artifacts unchanged, refresh or replace the operator token, and retry the publishing step only. Do not rebuild unless the artifacts or evidence are wrong.

## Post-Publish Verification

After publishing, verify that the tag, release metadata, artifacts, and checksums are publicly visible or visible to the intended repository audience:

```bash
gh release view v1.0.1
curl -LO https://github.com/karoc/adp/releases/download/v1.0.1/adp-1.0.1-linux-amd64
curl -LO https://github.com/karoc/adp/releases/download/v1.0.1/SHA256SUMS
sha256sum -c SHA256SUMS
```

Download and run at least one published binary from a temporary location and compare its `adp version` output with the release evidence. If a published artifact differs from the verified local artifact, remove or replace the release asset and record the correction in operator notes.
